# Deploy on Render (free web service)

This app runs as a Docker web service on Render. Ticket data needs an external Postgres (Neon free works). Daily scrape uses GitHub Actions (Render free has no reliable long cron).

## 1. Free Postgres (Neon)

1. Create a project at https://neon.tech
2. Copy the connection string (`DATABASE_URL`)

## 2. Deploy on Render

1. Push this repo to GitHub (already configured as `origin`)
2. Go to https://dashboard.render.com → **New** → **Blueprint**
3. Connect the `scrape-review` repo and apply `render.yaml`
4. In the `sme-tickets` service → **Environment**, set:

| Key | Value |
|-----|--------|
| `DATABASE_URL` | Neon connection string |
| `SCRAPER_USERNAME` | Topin admin username |
| `SCRAPER_PASSWORD` | Topin admin password |
| `ADMIN_PASSWORD` | (optional) override for `admin` login |

`SESSION_SECRET` and `INGEST_TOKEN` are auto-generated by the blueprint.

5. Deploy → open `https://sme-tickets.onrender.com` (exact URL shown in Render)

Default logins are in the main README (change passwords after first login).

## 3. Daily 9 AM IST ingest (GitHub Actions)

1. In GitHub repo → **Settings → Secrets and variables → Actions**
2. Add:
   - `APP_URL` = your Render URL (e.g. `https://sme-tickets.onrender.com`)
   - `INGEST_TOKEN` = same value as Render env `INGEST_TOKEN`
3. Workflow: `.github/workflows/daily-ingest.yml` (runs 03:30 UTC = 09:00 IST)

Manual run: Actions → **daily-ticket-ingest** → **Run workflow**.

## 4. One-time backfill (optional)

From your laptop (against production DB):

```bash
export DATABASE_URL='postgresql://...'   # Neon URL
uv run python -m tickets.jobs.ingest_cli --from-date 2026-08-01 --to-date 2026-08-21 --no-enrich
```

## Notes

- Free Render web services **spin down** when idle; first request after idle can take ~30–60s.
- Scraping credentials stay only in Render env vars — never commit `.env`.
